W-PS-2 · AI Career Coach Show what your portfolio proves, and what it does not. Agentic AI · GitHub + real job requirements · live demonstration · 24 hours. The story Rohan wants a backend internship. The job posting asks for APIs, SQL, testing, and deployment. His resume lists all four. His GitHub has six repositories, but which of those skills do they actually demonstrate? He adds database queries and tests to a project over the weekend. A one-time resume review will not notice. His assessment should change when his work changes. Build an agent that keeps the skill-gap assessment current. Problem overview Build an AI agent that compares a student's demonstrated GitHub skills with real job or internship requirements. It should identify evidence-backed gaps and reassess relevant skills when the repositories change. The challenge Discover real job or internship requirements. Analyze the student's actual GitHub repositories for demonstrated skills. Compare portfolio evidence with the requirements and explain the gaps. Detect repository changes and automatically reassess the affected skills. Demonstrate the loop: job requirements → repository evidence → gaps → code change → updated assessment. Room to grow Build the core loop within 24 hours. Extend it in directions such as these, or propose your own. These are optional extensions, not a feature checklist. Resume discovery: scan portfolio changes for new projects, achievements, skills, or contributions worth adding; draft evidence-backed resume updates. Career research: research relevant technologies, domains, roles, and companies to identify valuable skills and experience to build. Next steps: suggest learning or project opportunities and track progress. Separate future recommendations from achievements already demonstrated. A missing signal in the repository means “not demonstrated in this scope,” rather than proof that the student lacks the skill. Data and tools Job requirements: use real, publicly available job or internship postings and retain their source links. Portfolio evidence: use real GitHub repositories and identify the files or code supporting each assessment. Change detection: choose a practical mechanism, such as polling or GitHub webhooks.
